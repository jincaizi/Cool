Monster AI Refactor: Architecture Comparison

Current system has 3 root-cause design flaws. The refactor fixes them structurally.

Current Architecture (3 Root Flaws)

MonsterAI.cpp — 464 lines, single class, god object tendency
1. Struct Context MonsterAIContext is a struct — all mutations discarded on return. DefendBlockCount, CooldownTimer never persist.
2. Damage Flow TakeDamage → damage applied → NotifyHit (defense check here = too late). No pre-damage hook.
3. Instant Attack ResolveAttack() called during TransitionTo(Attack) — before animation plays. 0-frame reaction window.
4. NavMeshAgent + Knockback _self.position += velocity while NavMeshAgent is active — conflicting position writes.
5. Dead Behaviour Code Alert unreachable. Update() never called on any behaviour. Lifecycle ignored.

Key Structural Changes

Fixed at Root

  • Context → class (mutable, shared)
  • Damage pipeline: PreCheck → Calc → Apply → Notify
  • Attack: Windup → Active → Recovery sub-states
  • NavMeshAgent disabled during knockback
  • Behaviour lifecycle auto-managed by scheduler
  • Boss-ready: phase system, multi-attack patterns

Removed

  • MonsterAIContext struct → replaced by AIContext class
  • MonsterAI.cs (~464 lines) → split into AIBrain + StateMachine + Scheduler
  • AlertBehaviour (dead code)
  • Direct transform writes during NavMeshAgent active
