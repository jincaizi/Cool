Section 1: Damage Pipeline

The #1 bug: damage was applied before defense checks. The new pipeline fixes this structurally.

Current (Broken)
TakeDamage(data, dir)
  │
  ├─ _stats.TakeDamage(data)  ← 伤害已扣！
  └─ _ai.NotifyHit(data, dir)
       └─ if (Defend)
            return  ← 太晚了，血已经没了
New Pipeline
TakeDamage(rawData, dir)
  │
  ├─ PreDamageCheck(rawData, dir)
  │    ├─ Defend: front → reduce, side → full
  │    ├─ Shield: absorb
  │    └─ Invincible: block
  │    → returns finalDamage
  │
  ├─ _stats.ApplyDamage(finalDamage)
  │
  └─ PostDamageNotify(rawData, dir)
       ├─ VFX / FloatText / HitReact
       └─ AI state machine notified

IDamageModifier Interface

Each defense mechanism is a pluggable modifier, checked in order:

public interface IDamageModifier
{
    // Priority: lower = checked first. Defend=100, Shield=200, BossInvincible=0
    int Priority { get; }

    // Returns the modified damage amount. Can block completely (return 0).
    // Sets flags on the result to signal VFX, hit reaction, etc.
    DamageResult Modify(DamageContext ctx);
}

public struct DamageResult
{
    public float FinalDamage;
    public bool WasBlocked;      // no damage, no hit react
    public bool WasReduced;      // partial damage, maybe different VFX
    public bool ShouldKnockback; // defend may suppress knockback
}

How It Fixes the Original Bugs

Bug #1 伤害先扣再判 → PreDamageCheck 在扣血前执行
Bug #2 DefendDamageReduction 从未被用 → DefendModifier 读取配置并执行减伤
Boss-ready Boss 的无敌阶段只需加一个 InvincibleModifier(Priority=0)，不需要改 AI 代码
