Damage Pipeline: Edge Case Review

15 edge cases analyzed. The pipeline design holds, but needs 4 structural additions.

Revised Pipeline (with additions highlighted)

TakeDamage(DamageContext ctx)          // ctx carries flags: IsDoT, IsCritical, IgnoresDefense...
  │
  ├─ 1. PreDamageCheck
  │     Run IDamageModifier chain by priority (0 → N)
  │     Each modifier reads ctx, returns DamageResult
  │     ctx.RawDamage is progressively reduced
  │     ← NEW: ref DamageContext so modifiers mutate shared state
  │
  ├─ 2. Gate Check                  ← NEW
  │     If result.WasBlocked → skip to PostDamageNotify (no HP change)
  │     If IsDead && NoPosthumousProc → return
  │
  ├─ 3. ApplyDamage
  │     stats.HP -= result.FinalDamage
  │     Clamp HP to 0
  │     If HP ≤ 0 && !result.PreventDeath → flag pending death
  │
  ├─ 4. PostDamageNotify            ← Always fires, even on death
  │     ├─ result.HitReactLevel → AI state machine
  │     ├─ result.ShouldKnockback → movement system
  │     ├─ VFX, floating text
  │     └─ On-hit procs (lifesteal, thorns, poison)
  │
  └─ 5. Death Check
        If pending death → EnterDeath()
DamageContext (revised)
public class DamageContext
{
    // Input
    public DamageBlock RawData;
    public Vector3 HitDirection;
    public int AttackerId;
    public DamageFlags Flags;
    public float RawDamage;

    // Mutated by modifiers
    public float CurrentDamage;
    public int BlockCount;
}

[Flags]
public enum DamageFlags
{
    None = 0,
    IsDoT = 1<<0,
    IsCritical = 1<<1,
    IgnoresDefense = 1<<2,
    IsReflected = 1<<3,
}
DamageResult (revised)
public struct DamageResult
{
    public float FinalDamage;
    public bool WasBlocked;
    public bool WasReduced;
    public bool PreventDeath;
    public bool ShouldKnockback;
    public HitReactLevel ReactLevel;
}

public enum HitReactLevel
{
    None,       // Boss super armor
    Flinch,     // Brief interrupt
    Stagger,    // Medium stun
    Knockback,  // Push back
    Launch,     // Airborne
}

Edge Cases → Solutions

#Edge CaseSolution
1Multi-hit same frame — two players hit simultaneouslyUnity main thread = sequential. Each TakeDamage call is atomic. Safe by default.
2Death prevention — "survive with 1 HP" buffDamageResult.PreventDeath = true → skip death even if HP≤0
3Knockback suppression — boss super armor ignores pushresult.ShouldKnockback = false → KnockbackEvent not emitted
4Hit reaction variation — light vs heavy attackDamageResult.ReactLevel → AI FSM checks against current super-armor level
5DoT ticks — should not trigger hit stun or VFX spamDamageFlags.IsDoT → modifiers skip hit react, minimal VFX
6Damage reflection / thornsThornsModifier in PostDamageNotify emits reflected damage to attacker via EventBus
7On-hit procs — lifesteal, poison, status effectsPostDamageNotify → EventBus emits OnDamageDealt/OnDamageReceived, proc systems subscribe
8Defend angle vs fast-moving attackerAcceptable. Hit direction is sampled at collision frame. Design decision, not a bug.
9Shield + Defend stacking — which applies first?Priority system: ShieldModifier=200 (absorbs first), DefendModifier=100 (reduces remainder). Deterministic.
10Modifier state mutation — shield HP decreases, block count++Modifiers own their state (ShieldModifier.CurrentHP, DefendModifier.BlockCount). Modify() has side effects — explicit design choice.
11I-frames after hit — brief invincibility windowHitInvincibilityModifier(Priority=0) with configurable duration timer. Blocks all damage during window.
12Zero damage after reductionWasBlocked=true → skip VFX. WasReduced=true but damage>0 → play "glancing hit" VFX.
13Overkill — 10HP monster takes 1000 damageHP clamped to 0. Track OverkillDamage for boss "dramatic death" VFX (optional).
14Damage during death animationPreDamageCheck skips, ApplyDamage skips, but PostDamageNotify still fires for on-death procs.
15Combo damage scaling — consecutive hits deal moreAIContext tracks RecentHitCount + LastHitTime. ComboModifier reads this in PreDamageCheck.
