Unity-specific concerns: GC allocation, NavMeshAgent lifecycle, MonoBehaviour boundaries, Animator timing.

Issue 13: DamageContext GC Allocation Per Hit

DamageContext is created new DamageContext{...} every TakeDamage call. In an AoE hitting 30 monsters, that's 30 heap allocations in one frame.

Class (allocates)
public class DamageContext { ... }

// Every hit:
var ctx = new DamageContext { ... };
pipeline.Process(ctx);  // GC alloc
Struct + ref (zero alloc)
public struct DamageContext { ... }

// Every hit — stack allocation, zero GC:
DamageContext ctx = default;
ctx.RawData = data;
ctx.HitDirection = dir;
pipeline.Process(ref ctx);

→ Fix: DamageContext → struct, all pipeline methods take ref DamageContext.

Issue 14: Double OnUpdate on Transition Frame

If TransitionTo calls OnEnter→OnUpdate for the new state, and then ExecuteState also calls OnUpdate, the new state runs OnUpdate twice in the same frame.

// WRONG (TransitionTo runs OnUpdate, ExecuteState runs it again):
_fsm.EvaluateTransitions(_ctx);   // internally calls TransitionTo → OnEnter → OnUpdate
_fsm.ExecuteState(_ctx);          // calls OnUpdate again!

// FIXED — Three-phase execution:
public void Update(float deltaTime)
{
    _ctx.DeltaTime = deltaTime;
    _ctx.AttackCooldown -= deltaTime;
    _ctx.Movement.UpdateKnockback(deltaTime);
    TryFindTarget();

    // Phase 1: Evaluate (returns next state or null, NO side effects)
    var next = _fsm.EvaluateTransitions(_ctx);

    // Phase 2: Execute transition if needed
    if (next != null)
        _fsm.TransitionTo(next, _ctx);   // OnExit → swap → OnEnter (no OnUpdate)

    // Phase 3: Execute current state (always runs once)
    _fsm.ExecuteState(_ctx);             // OnUpdate
}

Issue 15: NavMeshAgent Resume() May Follow Stale Path

After knockback + hit recovery, Resume() sets isStopped=false but the agent still has its old path. It may move 1 frame towards the old destination before the new SetDestination overrides it.

public void Resume()
{
    _agent.ResetPath();       // ← Clear stale path to prevent 1-frame wrong movement
    _agent.isStopped = false;
}

public void ResetKnockback()
{
    _knockbackVelocity = Vector3.zero;
    _knockbackTimer = 0;
    // Only sync if agent is enabled; disabled agents reject nextPosition
    if (_agent.enabled)
        _agent.nextPosition = _self.position;
}

Issue 16: AIContext Stores Unity Object References — Stale Reference Risk

AIContext holds Animator, Target (Transform), Self (Transform). If a state stores the AIContext reference as a field and accesses it after the GameObject is destroyed → MissingReferenceException.

// AIStateBase — document the contract:
//
// IMPORTANT: States receive AIContext as a method parameter.
// Do NOT store AIContext as a field — it contains Unity Object references
// (Animator, Transform) that become invalid on GameObject destruction.
// All state access should happen through the method parameter,
// which is guaranteed valid for the duration of the call.

public abstract class AIStateBase
{
    // NO: private AIContext _ctx; // ← forbidden
    public virtual void OnEnter(AIContext ctx) { }
    public virtual void OnUpdate(AIContext ctx) { }
    public virtual AIStateBase EvaluateTransitions(AIContext ctx) { return null; }
    public virtual void OnExit(AIContext ctx) { }
    public abstract MonsterAIState StateType { get; }
}

Issue 18: EventBus Leak on Destroy-Without-Disable

OnEnable subscribes, OnDisable unsubscribes. But if the GameObject is destroyed directly (rare but possible via DestroyImmediate in editor), OnDisable might not fire.

private void OnDestroy()
{
    // Safety net: unsubscribe even if OnDisable was skipped
    EventBus.UnsubscribeTargeted<KnockbackEvent>(GetInstanceID(), OnKnockback);
    EntityDisplayManager.Instance?.Unregister(GetInstanceID());
    PhysicsRegistry.Instance?.Unregister(this);
}

Issue 20: Config is Shared — Must Be Read-Only at Runtime

MonsterConfig is a ScriptableObject asset. Multiple monster instances share the same config. If any runtime code writes to a config field, it corrupts all instances. Comment as invariant.

// MonsterConfig.cs header comment:
//
// INVARIANT: MonsterConfig is a shared ScriptableObject asset.
// All fields are read-only at runtime. States and modifiers read config
// values but NEVER write to them. State-specific mutable data lives in
// AIContext, not in config.
