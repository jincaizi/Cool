Issue 7: Attack Sub-State Timing — Animation vs Timer

The design says "Windup → Active → Recovery" but doesn't specify what drives the transitions. Two options:

Option A: Animation Callback
Attack anim → StateMachineBehaviour
  → AIBrain → AttackState
    → ResolveDamage()

Pros: frame-perfect sync with VFX
Cons: Requires new StateMachineBehaviour
      on monster anims, tighter coupling
Option B: Timer-Based ✅
Config fields:
  AttackWindupTime = 0.2f
  AttackRecoveryTime = 0.3f

AttackState.OnUpdate():
  if timer >= windupTime && !dealt
    → ResolveDamage()
  if timer >= windup+recovery
    → Transition out

Pros: Simple, data-driven, no new callbacks
Cons: Timing decoupled from anim frames

→ Choose Option B for now. Add config fields AttackWindupTime / AttackRecoveryTime. Comment explains: "For frame-accurate hit timing, replace with animation event callback in the future."

Issue 8: NavMeshAgent Position Sync After Knockback

Knockback moves transform directly. When knockback ends and agent resumes, it may warp back to pre-knockback position because agent.nextPosition wasn't synced.

// MonsterMovement.ResetKnockback() — add sync:
public void ResetKnockback()
{
    _knockbackVelocity = Vector3.zero;
    _knockbackTimer = 0;
    // Sync NavMeshAgent to current position to prevent warp-back.
    // Without this, the agent resumes from its last calculated position
    // which may be far from where knockback pushed the transform.
    if (_agent.enabled)
        _agent.nextPosition = _self.position;
}

Issue 11: AIContext Field Ownership

AIContext is a mutable class shared across all components. Without clear ownership, fields become spaghetti state. Solution: document ownership in comments.

// AIContext is the single source of truth for all AI-related mutable state.
// Ownership conventions (enforced by convention, not compiler):
//
// ── Owned by AIBrain ──
//   Target, DeltaTime, AttackCooldown
//
// ── Owned by AIStateMachine ──
//   CurrentState, StateTimer, PreviousState
//
// ── Owned by specific State ──
//   BlockCount (DefendState), CurrentAttackIndex (AttackState)
//
// ── Owned by DamagePipeline ──
//   LastHitResult, LastHitDirection, LastKnockbackForce
//
// Rule: a component should only write its own fields. Reading across
// ownership is fine. If you find yourself writing another component's
// field, add a method to that component instead.

Issue 12: Chase Destination Update Frequency

_agent.SetDestination(target.position) is called every frame during Chase. For 20+ monsters chasing the player, this causes unnecessary path recalculations. Not critical for current scope, but add a comment.

// MonsterMovement.Chase():
// Performance note: SetDestination is called every frame.
// If this becomes a bottleneck with many active monsters,
// throttle to every 0.25s: cache last destination + only update
// if target moved > 0.5m or timer elapsed.

Final File Structure

Monster/
├── AI/
│   ├── AIBrain.cs           ← Orchestrator (Update loop, target finding)
│   ├── AIStateMachine.cs    ← Global transitions + state switching
│   ├── AIContext.cs         ← Shared mutable state (class, with ownership docs)
│   └── States/
│       ├── AIStateBase.cs   ← OnEnter/OnUpdate/EvaluateTransitions/OnExit
│       ├── IdleState.cs     ← Timer → Patrol or Chase
│       ├── PatrolState.cs   ← Navigate waypoint → Idle or Chase
│       ├── ChaseState.cs    ← Follow target → Attack or Idle (target lost)
│       ├── AttackState.cs   ← Windup(no damage) → Active(resolve) → Recovery(exit)
│       ├── HitState.cs      ← Timer based on HitReactLevel → recover
│       ├── DeathState.cs    ← Terminal, triggers death animation
│       ├── DefendState.cs   ← Block counting, cooldown, counter-attack trigger
│       └── TauntState.cs    ← Random trigger on attack miss
│
├── Damage/
│   ├── IDamageModifier.cs   ← Interface for pre-damage hooks
│   ├── DamagePipeline.cs    ← PreCheck → Gate → Apply → PostNotify
│   ├── DamageContext.cs     ← Input (DamageBlock, flags, direction)
│   ├── DamageResult.cs      ← Output (final damage, react level, flags)
│   └── Modifiers/
│       ├── DefendModifier.cs    ← Front-facing damage reduction
│       └── IFrameModifier.cs   ← Post-hit invincibility window
│
├── MonsterEntity.cs         ← Thin wiring (pipeline + AI + events)
├── MonsterConfig.cs         ← + Attack timing, HitReact, IFrame fields
├── MonsterMovement.cs       ← + NavMeshAgent sync in ResetKnockback
├── MonsterSpawner.cs        ← (unchanged)
├── MonsterStats.cs          ← Simplified: only HP + attributes, no death logic
└── MonsterEvents.cs         ← (unchanged)
