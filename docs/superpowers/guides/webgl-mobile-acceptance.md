## 为什么这一块特别需要人工

它压在两条**桌面环境无论如何都碰不到**的东西上：

| 依赖 | 为什么桌面看不出来 |
|---|---|
| `Application.isMobilePlatform` | Unity 官方文档明写 WebGL 下 "**might not always report accurate information on all web browsers**"。已知实锤：**iPad 默认桌面视图时返回 `false`**、`SystemInfo.deviceType == Desktop` |
| `WebGLTouch.jslib` | 守卫是 `#if UNITY_WEBGL && !UNITY_EDITOR`——**编辑器里永远走不到这个分支**。它的第一次执行就是在真手机上 |
| 触屏 UI 的三条链路 | 摇杆模拟量、观察区拖拽、三个动作按钮——都只在**合成指针事件**下验过（`EventSystem.RaycastAll` 那条路），没有真手指 |

正因为第一条不可靠，代码里埋了一条**保险绳**：URL 参数 `?touch=1` / `?touch=0`，优先级高于自动判据。**第 1 项失败时先试它。**

## 0. 前置

- [ ] 手机连接到**与这台电脑同一个 Wi-Fi / 局域网**
- [ ] 记下本机局域网 IP（推导方式见下）

> ⚠️ **手机连不上 8000 是正常的，不是故障。** 服务端默认只监听 `127.0.0.1`（HTTP.sys 的 host 段是**字面匹配 `Host` 头**的），改成局域网前缀需要管理员权限或 URL ACL。所以走下面的**局域网代理**，**手机端的服务器地址填 `8002`，不是 `8000`。**

## 1. 确认本机局域网 IP

```bash
ipconfig
```

找"以太网"那一块。**本机有 3 个 IPv4，只有一个是真正的 LAN**（另外两个是 VMware 虚拟网卡）：

```bash
# 交叉验证：接口那一列才是 LAN IP
route print -4 | grep 0.0.0.0
```

> 本文档落盘时的值是 **`192.168.1.4`**（默认网关 `192.168.1.1`）。换网络后要重新确认。

## 2. 起三个服务

> **若服务已在运行可跳过。** 本文档落盘时三个都还开着。

```bash
# ① 游戏服务端（双栈：UDP 8000 + WS 8000；100 bots + 4 monsters）
cd E:/CodeForJob/Cool
dotnet run --no-build --project Server/Server3C.csproj -- 8000 --monsters 4 --bots 100
# 就绪判据：打印 "Server3C is running on port 8000"
#        与 "WebSocket listener started on http://127.0.0.1:8000/"
# 注意：不要用 netstat 找 PID——8000 的 TCP 行 PID 恒为 4（HTTP.sys）。
#       真要找进程用：tasklist | grep Server3C.exe

# ② 局域网 WS 代理（免管理员把本机 WS 暴露到局域网）
node production/verify/t8/t8-ws-lan-proxy.js --listen 8002 --target 8000
# 就绪判据：WS LAN proxy listening on 0.0.0.0:8002 -> 127.0.0.1:8000

# ③ 静态服务器（Bind 0.0.0.0，手机可直连）
cd E:/CodeForJob/Cool/Build/WebGL && python -m http.server 8080
```

- [ ] **若手机打不开 8080**：最可能是 **Windows 防火墙**挡了。放行 **8080** 与 **8002**（这一步需要管理员权限）

## 3. 验收步骤

### 3.1 打开

- [ ] 手机浏览器打开 **`http://<上一步的 IP>:8080`**

### 3.2 触控 UI 是否出现

- [ ] 屏幕上出现**左下摇杆**与**右下三个按钮**（攻击 / 防御 / 跳跃）

> **没有出现 → 在 URL 后面加 `?touch=1` 再打开**（例：`http://192.168.1.4:8080/?touch=1`）。
> 这是保险绳。**如果加了 `?touch=1` 也没用，那才是真问题——停下来报回来。**

### 3.3 触屏输入

- [ ] **摇杆半推 = 慢走，满推 = 快走**
      这是"模拟量没被丢弃"的判据。若半推与满推一样快，说明输入被归一化了（重写适配器就是为了修这个）
- [ ] **右半屏拖拽 → 视角跟着转**
- [ ] **松手立刻停**（视角不停 = 缺陷；停住不动时也要停，不能持续漂移）
- [ ] **三个按钮各按一次**：攻击 / 防御 / 跳跃 都有反应

### 3.4 进入世界

- [ ] 在"服务器地址"里填 **`<IP>:8002`**（**是 8002 不是 8000**），登录
- [ ] 能进世界、能看到自己的角色、能用摇杆移动
- [ ] 能看到**其他玩家**（白色胶囊/球体占位在移动）与**怪物**

### 3.5 性能

- [ ] 记录帧率观感：**流畅 / 尚可 / 明显卡顿**

> `--bots 100` 在跑。若明显不可用，**P3（AOI 大世界）的声称降级为"桌面浏览器演示"**，并写进已知边界话术卡。

## 4. 每条不通过意味着什么

| 症状 | 最可能的原因 | 怎么办 |
|---|---|---|
| 触控 UI 完全不出现，`?touch=1` 也无效 | `WebGLTouch.jslib` 没进包，或 binder 的判定链断了 | 报回来，这是真问题 |
| UI 出现但摇杆不动 | 摇杆组件或适配器接线 | 报回来 |
| 半推和满推一样快 | 模拟量在某处被 `normalized` | 报回来（重写适配器就是为了修它） |
| 松手后视角继续转 | 观察区没归零 | 报回来 |
| 按钮没反应 | 三个按钮的注入点没生效 | 报回来 |
| 连不上服务器 | 地址填了 8000 而不是 8002；或防火墙 | 先确认填的是 8002 |
| 8080 打不开 | Windows 防火墙 | 放行 8080 |
