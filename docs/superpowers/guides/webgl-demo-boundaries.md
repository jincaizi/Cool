# 已知边界话术卡（面试现场用）

> 用法：面试时放在手边。**每条都是"被问到 → 诚实说 → 但这么说的结果是让你加分"。**
>
> 原则：**主动说出边界比被问出来强。** 说"这里还没做"并给出为什么、以及你打算怎么排，展示的是判断力；被面试官发现才承认，展示的是没想清楚。

---

## 一、先主动亮出来的三件事

这三条是**你主动说**的，别等人问。它们是你这个项目里最值钱的部分。

### 1. 传输层做了抽象，然后把两端统一到同一条路径

> "一开始我实现了 KCP over UDP。为 WebGL 加 WebSocket 的时候我去查了应用层的调用点，发现**四个发送点全部用的是默认的 `MessageFlags.Reliable`**——KCP 的不可靠通道从来没被调用过。
>
> 对有序可靠的数据，KCP 相对 TCP 只多一个更激进的重传超时，**队头阻塞两者都有**。所以我把 PC 和浏览器统一到同一条 WebSocket 路径，只在最底层平台通道上分叉。KCP 保留为可切换的第二实现，没删。
>
> 关键不是我选了哪个协议，而是**我发现原来的选择没有带来我以为的收益**。"

**为什么这条值钱**：它证明你会回头验证自己的设计假设，而不是"因为我听说 KCP 游戏都用"。

### 2. 伤害由服务端掷骰，客户端结构上算不出来

> "玩家打怪的伤害不是客户端算的。我能给你看一条协议证据：`source=10 skill=20002 target=2000001 damage=240.0 remaining=-90`——**这个 240 是服务端掷的**，客户端只负责播表现。"
>
> "被打也一样：服务端把 `DamageResult` 发过来，客户端用**协议里的权威余血**驱动血条，而不是自己减一个本地计数器。"

**为什么这条值钱**：这是"服务端权威"从口号变成可验证事实的地方。

### 3. 验证是自动化的，不是"我手动点过"

> "浏览器端的验收我用 headless Chrome + CDP 驱动，不是手点。有一条判据是这样的：我数**双向帧数**并且抽查帧的字节内容，还有一条是反射门禁——它断言协议层不许出现某种会触发 IL2CPP 反射缺口的类型声明。"
>
> "状态机那一层我用 Node 单测覆盖，因为那段 JS 是唯一的浏览器边界、也是最容易错的地方。零依赖，`node --test` 就跑。"

**为什么这条值钱**：它说明你会**为难以测试的东西造测试手段**，而不是绕开它。这在网络/客户端岗位上是区分度很高的能力。

## 二、边界与应答

### ① 为什么用 WebSocket？UDP 不是更适合游戏吗？

**诚实说**：浏览器**没有** UDP。这是平台约束，不是取舍。

**补充**：即使不看这条，我的应用层也只用可靠消息（见上面第一条）。真要做"丢包就丢"的位置包，浏览器端的答案是 WebRTC DataChannel，不是 KCP。

> **准备接的一句**："所以这个选择在 WebGL 上是**被约束的**，不是**最优的**——但在我的消息模型下它和最优没有区别。"

### ② 服务端权威到什么程度？死了会怎样？

**诚实说**：**服务端没有复活**。玩家死后重连即满血，我用"重连当复活"顶上演示可用性。

**为什么**：死亡/复活的服务端状态机是独立一个阶段（P8）的范围，本次优先保证**伤害裁决与 AOI 的权威性**做对。

> **主动接一句**："出生点我 2026-10-13 搬到了湖东岸——**站在出生点不动不会被任何怪发现**（六只怪的'感知半径 + 巡逻半径'全都不覆盖它；`--monsters 6` 挂机 3 分钟实测 0 伤害）。但**地图不保证安全**：离开出生点朝原点方向走约 15m 就会踏进 [0] Wolf 的感知圈，之后照样会被它追上打死、送回选人界面重登——数量从来不是安全开关，`--monsters` 只决定场上有几只、看得到哪些（6 才含新的 DogKnight 与 SpiderBoss）。"

> **2026-10-17 第三次搬迁更新这句**（出生点 → **`(-15, 0.3, -30)`**，布局同批收紧收进陆地）：挂机仍安全——
> 六槽位对出生点全有余量（最近 **[2] Slime** 15.8m > 8+5，余量 +2.8m）；"走出约 15m 进 [0] Wolf"已不成立，
> 改为**朝 (0,0,-35) 走约 3m 进 [2] Slime 的感知圈**（[0] Wolf 现在距出生点 33.5m，巡逻圈够不着）。

### ③ 其他玩家是什么？远处的为什么变胶囊？

**诚实说**：其他玩家（真人 + 压测 bot）现在都是**真模型**——与本地角色同一条外观目录，走/跑动画由快照位置反推的速度驱动。**60m 外、或超出每帧 Full 预算**时降档为**代理**（条目没配 `Proxy` 预制体时是运行时胶囊）；怪物同理走模型目录（没配的模板仍是球体占位）。名字板还没接。

**为什么**：同步与 AOI 的正确性先做对（位置、朝向、进出视野、可见集合——服务端权威的那部分），然后才是"一个人看起来像一个人"；分档是**同屏人数上来时还能跑**的成本开关——`?full=` 可以在 URL 上现场扫每帧预算，`?fulldist=` 改进入距离。

> **主动接一句**："近处是真模型、远处是代理——升/降档按**距离迟滞 + 每帧预算**决定；手机上我就是用 URL 参数把预算扫了一遍定下来的，记录在 `production/verify/`。名字板还没接。"

### ④ 移动端输入怎么做的？

这条是**可以展开聊设计**的点，不是防守。

> "我**重写**了摇杆适配器。原来那个读的是三个在 `InputManager.asset` 里根本不存在的轴，一调用就抛异常；而且它把输入归一化了，**推一半和推满一样快**。重写后保留了模拟量，半推就是半速。"
>
> "判定移动端这件事我做了三层 + 一个手工兜底：`Application.isMobilePlatform` 是主判据，但**Unity 官方文档明说 WebGL 下它可能不准确**——有实锤是 iPad 的默认桌面视图会让它返回 false。所以我叠了一层触摸特性检测，再叠一个 URL 参数 `?touch=1` 强制打开。"
>
> "**面试现场如果我手机上的触控 UI 没出来，我会直接加这个参数给你看。**"

**为什么这条值钱**：它同时展示了"发现并修掉一个会崩的实现"、"知道平台判定的不可靠性"、"为不可靠的东西留了人工出口"。

### ⑤ 包体 / 首屏加载？

**诚实说**：**没做优化，也没测量**。这是显式决定：先把形态落地。

**为什么**：包体的大头是资源（模型/贴图），先清未使用资源才是主要杠杆，代码裁剪不是。

> **可以补**："构建日志里有准确数字，但我不想用一个没对照过的数字糊弄你。"

### ⑥ 有鉴权吗？会被别人连上吗？

**诚实说**：**没有鉴权**。知道 URL 就能连。

**为什么**：这是演示形态的刻意取舍——目的是让面试官扫码就能玩；加鉴权会把"发一个链接"变成"发一个账号"。

> **主动接**："生产环境要加的是：连接鉴权 + 速率限制 + 每连接的资源上限。现在的服务端对连接数没有任何约束。"

### ⑦ 打击感 / 受击表现做到哪一步了？

**诚实说**：Hit 层**只有三种状态可达**——受击、防御受击、眩晕。**击退复用受击剪辑**；没有独立的击退/浮空状态；倒地、死亡、浮空的表现层**没做**。

**为什么**：状态机与伤害链路是通的，表现层是显式 backlog。

> **主动接**："玩家死亡后**不能动、不能施法、约 3 秒复活**——这条逻辑是验过的；缺的是**看起来对**。"

### ⑧ 断线怎么办？

**诚实说**：**不自动重连**，断开后回到选人界面重新登录。

**补充**：之前这里有个缺陷——断线后选人面板不回来，等于卡死只能刷新；已经修了。

> **可以接**："切后台标签页也可能被服务器超时清理，这个我列进已知边界了。"

### ⑨ 中文/字体

**诚实说**：WebGL 构建里，**浮层的中文标签显示不出来**——字体子集没覆盖运行时拼的字符串。数字和英文正常。

**为什么**：字体子集是打包时定的，运行时字符串没进去。

> **主动接**："所以验收读数是靠字段顺序和英文锚点读的。这是个表现层缺口，不影响逻辑。"

### ⑩ 测试覆盖到什么程度？

**诚实说**：三条线——服务端 xunit、Unity EditMode、Unity PlayMode（**要三种服务器配置跑，取并集**）。

**关键补充**：**有一类缺陷这套测试结构上抓不到**——只在 IL2CPP/WebGL 下才现形的。我踩过一个：protobuf-net 在 IL2CPP 下会调一个未实现的反射接口，导致某种集合类型的成员**静默解码失败**。

> **主动接**："那次的教训是：**只在 Mono 上跑的测试证明不了 WebGL 上没问题**。所以我后来加了一条反射门禁，把这个类型形状钉住。"

### ⑪ 能穿过怪/Boss 吗？

**诚实说**：**现在挡得住，但这是纯客户端判定**——服务端不模拟玩家移动、也不校验重叠，所以**改客户端就能穿模**（这跟伤害不同：伤害是服务端掷骰，客户端算不出来）。怪物视图的碰撞体在运行时按模型包围盒建（`NpcBodyCollider`），尺寸随模型走，只与本地玩家层碰撞（层矩阵：`NpcBody`×玩家层，其余全关）——攻击检测按组件筛选、地面检测读 `CharacterController.isGrounded`，都不受影响。

**为什么这么排**：服务端权威这一阶段只做了**伤害裁决与 AOI 可见集合**；玩家移动的权威校验（含推出重叠/卡位）是独立一块，本次按"演示里先不穿 Boss"的最小代价落地。

## 三、演示操作建议（给自己看）

| | |
|---|---|
| **怪物数量** | `--monsters` 只决定**场上有几只、看得到哪些**（6 才含新怪 DogKnight / SpiderBoss）——**不是安全开关**（安全与数量无关）。出生点本身自 2026-10-13 搬点后对**全部六只**都安全：站在出生点不动不会被发现，实测挂机 3 分钟 0 伤害 |
| **那想活着怎么办** | **动起来 / 打回去**（设计意图）。出生点安全**只管出生点**：走出约 15m 就进 [0] Wolf 的感知圈被追；阵亡 = 回选人界面重登（重登即满血，见上文②） |
| **如果想演 P5（怪物 AI）** | 用 `--monsters 2`：场上怪少，Slime 的巡逻/追击看得清（Wolf 仍在场，见上面两行） |
| **如果想演 P3（AOI 大世界）** | 必须 `--bots 100`；浮层的"远程实体"计数会从 0 跳到 8–9 |
| **触控 UI 没出来** | 在 URL 后面加 `?touch=1` |
| **断线了** | 回选人界面重新登录（就是"复活"） |
| **手机连不上服务器** | 检查地址是不是填了 **8002**（不是 8000） |

> **"挂机多久会死"现在的口径**：**站在出生点**不动**不会死**——2026-10-13 活体验证（`--monsters 6`，3 分钟）0 伤害、
> 未阵亡。但**离开出生点**就回到旧的危险里：单只 Wolf 的物理下限是 100 HP ÷ 15 dps（`CombatRules` 50002）≈ **6.7 秒**，
> 而且从**接触之后**才开始计，还要加上它追击贴身的路程。旧的"约 7 秒"出自更早的实测（4~6 只怪一起围在脸上），
> 只当"**十几秒起，最坏接近半分钟**"理解即可，别当成精确读数。
>
> 2026-10-17 第三次搬迁（出生点 → `(-15,0.3,-30)`、布局收紧）后本口径不变：出生点挂机仍 0 伤害
>（全六槽位几何守卫 + 2700 tick 零施法的用例已按新坐标重算并全绿；走位提醒见 §二 ② 的更新行）。

## 四、一句话总结（如果只让你说一句）

> "这是一个服务端权威的 3C 战斗原型：伤害裁决、AOI 可见集合、怪物 AI 都在服务端跑，客户端只做表现和输入；传输层做了抽象，我把两端统一到了浏览器也支持的那条路径上。**能演的我都演给你看，没做的我直接说是哪一块、为什么排在后面。**"
