dotnet build Client/Client.csproj -c Release

run-poc.sh runs:
  Server --port 47114 --hostname 127.0.0.1 --client-pub keys/client.pub ... (wrong-identity case)
  Client --port 47114 --server-pub keys/wrong-server.pub --mode wrong-identity
  Server --port 47113 --hostname 127.0.0.1 ... (UDP main case)
  Client --port 47113 --server-pub keys/server.pub --mode main
  Server --transport tcp --port 47115 --hostname 127.0.0.1 ... (TCP framing case)
  Client --transport tcp --port 47115 --server-pub keys/server.pub --mode main

## Emulator run

emulator.exe -avd Medium_Phone_API_36 -no-window -no-audio -no-boot-anim
  -gpu swiftshader_indirect -no-snapshot-load -no-snapshot-save
  -netdelay none -netspeed full

bash run-unity-poc.sh

run-unity-poc.sh:
  adb reverse tcp:47120 tcp:47120
  Server --transport tcp --port 47120 --hostname 127.0.0.1 --client-pub keys/client.pub ...
  adb install -r UnityPoc/Build/KcpSecurityPoc.apk
  adb shell am start -n com.poc.kcpsecurity/com.unity3d.player.UnityPlayerActivity
  adb logcat -d -s Unity:V > out/unity-logcat.txt

Emulator limitation: the guest has no working route to 10.0.2.2 (ip route get and ping
return "Network is unreachable"; eth0 policy rules exist but no route tables), so the
Unity leg uses TCP framing through adb reverse. The .NET POC exercises UDP; Noise is
transport-agnostic and the provider/IL2CPP compatibility is what the Unity leg verifies.
The only installed emulator image is x86_64, so the APK was built for ARM64 + x86_64
but the executed ABI is x86_64.
